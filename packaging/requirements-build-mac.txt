# Allied Vision's vmbpy bindings, not on PyPI. Vendored locally instead of
# fetched from anywhere, see packaging/vendor/README.md for why this is
# safe to redistribute and what it does and does not cover.
#
# Mac gets 1.0.4 specifically, not the newer 1.2.2 used for Windows.
# vmbpy checks the installed native Vimba X Runtime's version the moment
# it is imported, and this Mac's actual Vimba X install only provides the
# older native runtime 1.0.4 was built against; installing 1.2.2 here
# raised vmbpy.error.VmbSystemError at import time (Expected: 1.3.1,
# Found: 1.0.5) instead of working. Allied Vision's own newer Vimba X SDK
# releases are Windows/Linux focused, so there is no guarantee a Mac
# install of Vimba X ever reaches the 1.3.1-era native runtime 1.2.2
# wants. If that changes (a newer Vimba X SDK confirmed working on Mac),
# update this line and packaging/INSTALL.md together.
#
# Path is relative to the PROJECT ROOT, not to this file's own location;
# pip resolves paths inside a requirements file that way, not relative to
# the file itself the way -r includes work.
packaging/vendor/vmbpy-1.0.4-py3-none-any.whl
